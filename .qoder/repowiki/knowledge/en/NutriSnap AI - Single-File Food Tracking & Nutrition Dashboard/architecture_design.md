The entire application lives in one script (`app.py`) organized into logical sections: a static `NUTRITION_DB` dictionary of ~50 foods with per-100g macros and typical gram weights; a COCO class ID-to-food mapping used by the YOLO detector; a model-loading layer (`load_yolo`, `load_hf_classifier`) that lazily imports `ultralytics.YOLO` and `transformers.AutoImageProcessor`/`AutoModelForImageClassification` with try/except fallbacks; a food analysis pipeline (`analyze_image`) that first runs YOLO detection on BGR frames, falls back to the HuggingFace classifier when no detections are found, estimates portion size from bounding-box area ratios, looks up nutrition via `calculate_nutrition`, logs each result to a local `meal_log.csv`, and draws annotated overlays with OpenCV; a dashboard builder (`build_dashboard`) that reads the CSV with pandas and renders four Plotly figures (daily calories bar, macro pie, weekly trend line, top foods horizontal bar); and a Gradio UI (`build_ui`) exposing three tabs (Upload & Analyze, Dashboard, Food Log, plus a Tips tab) wired to event handlers. Dependencies flow strictly downward: UI → pipeline → model loaders → CSV persistence; there is no external package structure or import graph beyond this file.
